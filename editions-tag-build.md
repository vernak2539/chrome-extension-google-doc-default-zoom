Base and Extended are built from the same source with Plasmo tags: `pnpm build:base` / `pnpm build:extended` (`plasmo build --hoist --tag=<edition>`), and `build`, `package` and `dev` mean Extended. Output is `build/<target>-<edition>` (e.g. `build/chrome-mv3-base`, `.zip` next to it); Plasmo names it `${target}-${tag}` and reads `.env.<tag>`. `package.json` `manifest` uses `$PLASMO_PUBLIC_EXT_NAME`, `$DEBUGGER_PERMISSION` and `$FIREFOX_EXT_ID`, filled from the committed `.env.base` / `.env.extended` (`.gitignore` has `!.env.base` / `!.env.extended` after `.env*`). A missing variable does not fail the build: an empty `$DEBUGGER_PERMISSION` silently drops the permission and a missing `PLASMO_PUBLIC_EXT_NAME` falls back to the Extended `displayName`. `pnpm check:editions` (`bin/check-edition-build.mjs`) checks every `build/<target>-<edition>` and exits 1 on any mismatch or when no build exists. Icons are `assets/icon.base.png` / `assets/icon.extended.png`. Plasmo's icon lookup (`Fc` in `node_modules/plasmo/dist/index.js`) tries, per icon name, `icon.<tag>.<NODE_ENV>.png`, `icon.<NODE_ENV>.png`, `icon.<tag>.png`, then `icon.png`, so an `icon.production.png` would override both tagged icons. Code branches on `IS_EXTENDED_EDITION` from `src/utils/edition.ts` (`process.env.PLASMO_TAG === "extended"`, unset means Base). The old `transform-ext` scripts and `EXTENDED_ONLY` markers are gone.
